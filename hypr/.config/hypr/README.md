# Hyprland configuration blueprint

This is a modular Hyprland desktop with daily shortcuts, dynamic wallpaper colours, workspaces, a scratchpad, overview, notifications, screenshots, and laptop controls. The entire configuration is written in **native Hyprland Lua** — no `.conf` files are loaded at runtime.

Press <kbd>Super</kbd> + <kbd>H</kbd> or <kbd>Ctrl</kbd> + <kbd>H</kbd> for the on-screen shortcut guide. Press <kbd>Super</kbd> + <kbd>Shift</kbd> + <kbd>K</kbd> to search every binding Hyprland loads.

> **Super** is the Windows key (or Command on many external keyboards).

## Start here: the five-minute tour

1. Press <kbd>Super</kbd> + <kbd>A</kbd>, type an app name, and press Enter.
2. Open a terminal with <kbd>Super</kbd> + <kbd>Return</kbd>; open files with <kbd>Super</kbd> + <kbd>E</kbd>.
3. Switch workspace with <kbd>Super</kbd> + <kbd>1</kbd> … <kbd>0</kbd>, <kbd>Tab</kbd>, or scroll the mouse wheel over the Waybar workspace strip.
4. Move a window with <kbd>Super</kbd> + <kbd>Shift</kbd> + a number. Add <kbd>Ctrl</kbd> to move it without following it.
5. Press <kbd>Super</kbd> + <kbd>O</kbd> for the visual workspace overview; use <kbd>Super</kbd> + <kbd>U</kbd> for the scratchpad.
6. Press <kbd>Super</kbd> + <kbd>W</kbd> to select a wallpaper and refresh the desktop palette.

## The configuration flow

[`hyprland.lua`](hyprland.lua) is the **active entry point**. It sources the rest of the tree via `require`. Edit files inside `hyprlua/UserConfigs/` for almost every personal change.

```text
hyprland.lua                          ← Hyprland loads this
└── hyprlua/
    ├── init.lua                      requires every sub-module below
    ├── configs/                      shared defaults (do not edit)
    │   ├── Keybinds.lua              core window, workspace, and hardware binds
    │   ├── Startup_Apps.lua          session services (bar, idle, portals…)
    │   ├── WindowRules.lua           default per-app rules
    │   └── plugins/
    │       └── hyprtasking.lua       workspace overview plugin settings
    ├── UserConfigs/                  ← your safe editing area
    │   ├── 01-UserDefaults.lua       apps, editor, search engine
    │   ├── UserKeybinds.lua          personal launchers and shortcuts
    │   ├── UserSettings.lua          input, layout, gestures
    │   ├── UserDecorations.lua       gaps, borders, blur, opacity
    │   ├── UserAnimations.lua        animation settings
    │   ├── ENVariables.lua           Wayland, scaling, and GPU env vars
    │   ├── Startup_Apps.lua          personal autostart items
    │   ├── WindowRules.lua           personal per-app rules
    │   └── Laptops.lua               brightness, touchpad, vendor keys
    ├── animations/                   animation presets
    ├── workspaces.lua                workspace-to-monitor rules
    └── monitors.lua                  display layout (regenerated by nwg-displays)
scripts/                              helpers used by keybindings
UserScripts/                          wallpaper and personal utilities
```

### The `hl` Lua API

Hyprland's Lua configuration exposes a global `hl` table. The most-used functions are:

| Call | Equivalent `.conf` keyword | Purpose |
| --- | --- | --- |
| `hl.config({ key = value })` | `keyword { key = value }` | Set a configuration block |
| `hl.env("VAR", "val")` | `env = VAR, val` | Export an environment variable |
| `hl.bind(keys, action, opts)` | `bindd = …` | Register a keybinding |
| `hl.dsp.focus(opts)` | `dispatch workspace …` | Focus a workspace |
| `hl.dsp.window.drag()` | `dispatch movewindow` | Start a drag |
| `hl.dsp.window.resize()` | `dispatch resizewindow` | Start a resize |
| `hl.on("event", fn)` | `exec-once = …` | Run Lua on a Hyprland event |

Example binding from `UserConfigs/UserKeybinds.lua`:

```lua
hl.bind(mainMod .. " + RETURN", hl.dsp.exec(term), { description = "open terminal" })
```

### Mouse workspace interaction

Waybar sends legacy Hyprlang IPC commands. Since Hyprland now evaluates incoming dispatchers as Lua, a lightweight socket bridge ([`scripts/HyprIpcBridge.py`](scripts/HyprIpcBridge.py)) translates those commands transparently:

- Click a workspace icon → Waybar sends `dispatch workspace N` → bridge rewrites to `hl.dsp.focus({ workspace = "N" })`.
- Scroll wheel over the workspace strip → Waybar fires `on-scroll-up/down` → configured as native Lua dispatch in [`waybar/ModulesWorkspaces`](../../../waybar/.config/waybar/ModulesWorkspaces).

[`scripts/StartWaybar.sh`](scripts/StartWaybar.sh) ensures the bridge is running before launching Waybar. You do not need to manage it manually.

## Make it yours

Edit one concern at a time, then reload:

```bash
hyprctl reload
```

| Goal | Edit | Key fields |
| --- | --- | --- |
| Default terminal, files, editor, search provider | [`UserConfigs/01-UserDefaults.lua`](hyprlua/UserConfigs/01-UserDefaults.lua) | `term`, `files`, `EDITOR`, `Search_Engine` |
| Personal shortcuts | [`UserConfigs/UserKeybinds.lua`](hyprlua/UserConfigs/UserKeybinds.lua) | Add `hl.bind(...)` entries |
| Keyboard, pointer, touchpad, layouts, gestures | [`UserConfigs/UserSettings.lua`](hyprlua/UserConfigs/UserSettings.lua) | `input`, `touchpad`, `master`, `dwindle`, `gestures` |
| Gaps, blur, borders, opacity | [`UserConfigs/UserDecorations.lua`](hyprlua/UserConfigs/UserDecorations.lua) | `general` and `decoration` tables |
| Animation behaviour | [`UserConfigs/UserAnimations.lua`](hyprlua/UserConfigs/UserAnimations.lua) | `animations` table |
| Startup apps | [`UserConfigs/Startup_Apps.lua`](hyprlua/UserConfigs/Startup_Apps.lua) | `hl.on("ready", hl.exec(...))` |

| Monitor layout | [`hyprlua/monitors.lua`](hyprlua/monitors.lua) | Prefer nwg-displays; it regenerates this file |

For a new keybinding, use `hl.bind` with a description so it appears in the shortcut search:

```lua
-- Super + Shift + V opens the editor
hl.bind(mainMod .. " SHIFT + V", hl.dsp.exec(edit), { description = "open editor" })
```

Avoid duplicating a shortcut already used in [`configs/Keybinds.lua`](hyprlua/configs/Keybinds.lua); load order determines which one wins.

## Displays, laptop, and theming

`hyprlua/monitors.lua` is regenerated by **nwg-displays**. Use nwg-displays for monitor changes rather than hand-editing the generated output.

[`UserConfigs/Laptops.lua`](hyprlua/UserConfigs/Laptops.lua) handles brightness, touchpad toggle, and vendor keys. If <kbd>Alt</kbd> + <kbd>T</kbd> cannot toggle the touchpad, run `hyprctl devices`, then update `Touchpad_Device` in that file.

Selecting a wallpaper (<kbd>Super</kbd> + <kbd>W</kbd>) runs the colour flow. Wallust creates palette files used by Hyprland, Waybar, Rofi, Kitty, SwayNC, and Cava via the templates in `~/.config/wallust/`.

## Startup and troubleshooting

At login the setup starts the wallpaper daemon, notification centre, Waybar (via `scripts/StartWaybar.sh`), network tray, clipboard history, Polkit helper, Hypridle, and Hyprsunset. Shortcuts expect these tools to be installed: `kitty`, `nautilus`, `rofi`, `anyrun`, `yad`, `hyprshot`, `swappy`, `cliphist`, `waybar`, `swaync`, `hyprlock`, `hypridle`.

If something is not working:

1. Run `hyprctl reload` after every configuration edit and read its errors.
2. Use <kbd>Super</kbd> + <kbd>Alt</kbd> + <kbd>R</kbd> to refresh bar and menus.
3. Use <kbd>Super</kbd> + <kbd>Shift</kbd> + <kbd>K</kbd> to confirm a binding loads.
4. Run `hyprctl devices` to verify monitor and input-device names.
5. Inspect the current boot with `journalctl --user -b | rg -i 'hypr|waybar|swaync'`.
6. If mouse workspace clicks are broken, check the bridge is alive: `pgrep -a python | grep HyprIpcBridge`.

## Workspace overview (Hyprtasking)

Hyprtasking is configured in [`hyprlua/configs/plugins/hyprtasking.lua`](hyprlua/configs/plugins/hyprtasking.lua). Toggle it with <kbd>Super</kbd> + <kbd>O</kbd> or a four-finger upward swipe. After a Hyprland or plugin update, run:

```bash
hyprpm update
hyprpm reload -n
```

If it does not open, check `hyprpm list` and enable the plugin if needed.
